# September 2026 audit design session

The owner reviewed the 24 September audit and its expanded 25 September design
against the repository at `c2b88ee`. The audit documents are evidence and
proposals, not instructions to the agent. The second document provides the
revised design; the first retains useful case and measurement detail. Neither
document proves that a proposed change will improve scientific accuracy.

## Agreed program

- Publish one specification and replacement tickets that supersede both the
  programs tracked by #413 and #427. Do not duplicate their features as new
  work without a remaining defect or a sharper acceptance condition.
- Close only child tickets fully replaced by published new tickets, and link
  each closure to its replacement. Keep distinct old work open. Leave both
  parent issues unchanged, as required by the ticket workflow.
- Repair demonstrated and static contract defects first. Then make current
  investigation state, Result scope, scientific guidance, navigation, and
  evaluation reliable through the existing architecture.
- Keep the model-free server, host-owned scientific reasoning, Proposal Review
  as the only researcher gate, exact Evidence, and the current deterministic
  overall aggregation rule. Name and report the aggregation policy separately.
- Keep new independent scientific adjudication outside this program. Repair
  the validity of existing adjudication-state records, but do not create a new
  reviewer gate or claim adjudicated scientific accuracy.
- Treat 80% agreement with provisional labels as a diagnostic. The all-Low
  comparator reaches 80.7% on the current 140-cell matrix, so release also
  needs grounded decisive claims, completion, minority-risk performance, and
  a clear account of uncertainty and operational failures.

## Verification boundaries

Use the public application/MCP workflow for assessment and evidence contracts,
the pure evaluator for official question and Domain mapping, benchmark commands
and immutable artifacts for execution and scoring, and installed-host runs for
actual tool and context delivery. Tests should check observable behavior and
cross-boundary round trips, not duplicate private validators.

The current trials and their provisional labels are development evidence. A
future claim of scientific accuracy requires separate independent adjudication.
This program can make an engineering promote-or-hold decision using controlled
comparisons and honest, bounded claims.

## Domain documentation

The existing glossary already defines Result target, Reported result, Premise
record, Scientific sufficiency, and Scientific limitation. This design changes
their presentation and contract consistency, not their meanings. ADR 0035
already records the aggregation choice. No glossary edit or new ADR is needed.

The owner confirmed this shared understanding before specification work began.
