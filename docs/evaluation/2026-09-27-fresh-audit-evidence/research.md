# Research notes for the 2026-09-27 agent audit

I read the README, `CONTEXT.md`, the packaged assessment skill, and the current evaluation/audit notes. `rob2-kit` already has a host-owned ReAct loop, typed MCP tools for source navigation/search/read/render/evidence, a Result-bound working checkpoint, one Proposal Review gate, deterministic RoB 2 logic, and trace/comparison/qualification machinery. The live gap is whether hosts resolve and justify decisive scientific premises from the right passages. New orchestration, reviewer agents, generic search quotas, or another overlapping tool are not supported by these sources.

No source below establishes that this system can achieve 80% scientific accuracy. Treat 80% as an independently adjudicated target on exact approved Results, with class support and uncertainty reported; provisional label agreement and a passing workflow are not accuracy evidence.

## Primary sources and what transfers

| Source | Source-supported finding | Specific use here and limit |
| --- | --- | --- |
| [Cochrane Handbook, Chapter 8](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-08) | RoB 2 evaluates a particular trial result; signalling answers and judgments require written justifications, and an algorithm proposes rather than certifies judgments. | Defines the scientific target for #475/#476: adjudicate the exact Result and premise warrant, including matching-label cases that could be unsupported reassurance. The Handbook is domain authority, not a retrieval or model benchmark. |
| [ReAct paper](https://arxiv.org/abs/2210.03629) | The paper studies interleaved reasoning and external actions/observations for knowledge and interaction tasks. | The existing host loop already has this shape. Assess whether a trace shows a premise unresolved despite an available search/read/recovery action; the paper does not establish an optimal search count or justify adding another orchestrator. Its reported results are task/model-specific. |
| [MCP server tools specification, 2025-11-25](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2025-11-25/server/tools.mdx) | MCP standardizes discovery/invocation metadata and typed tool calls; models may select and invoke tools from context. | Confirms MCP as a provider-neutral transport boundary. A valid schema, receipt, or evidence handle does not prove that a passage entails a scientific premise. Keep identity/provenance/structure server-validated and premise sufficiency host-owned, as the repo does. |
| [Anthropic, Writing effective tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents) | Their tool-use evaluations favor distinct purposes, clear input/output descriptions, high-signal returns, realistic multi-step tasks, trace inspection, and held-out checks. They report tool naming effects vary by LLM. | Apply only after a trace identifies a concrete selection/friction failure in the existing 18-tool surface. Test any description/schema change across more than one host/model; these are Anthropic engineering observations, not independent medical-accuracy evidence. |
| [Anthropic, Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | This engineering account treats full evolving agent context (instructions, tools, retrieved data, and history) as a finite resource that must be curated each turn. | Useful framing for #474's end-to-end delivery measurement. It is guidance, not a controlled finding that shorter context preserves scientific accuracy; do not remove official qualifiers, contrary evidence, or recovery paths on this basis alone. |
| [Liu et al., “Lost in the Middle,” TACL 2024](https://aclanthology.org/2024.tacl-1.9/) | Controlled multi-document QA and key-value studies found substantial position effects, and marginal gains from retrieving more documents in one QA case study; the models included GPT-3.5-Turbo and Claude 1.3. | Justifies testing context position/volume as a possible source of missed evidence, not assuming longer or shorter is better. For #474, compare complete reconstructions with identical evidence/guidance but different delivery shapes, and score premise validity. The models/tasks are older and not clinical RoB 2. |
| [Agarwal et al., “Synthesizing scientific literature with retrieval-augmented language models,” Nature 2026](https://www.nature.com/articles/s41586-025-10072-4) | The authors evaluate retrieval-backed scientific synthesis with expert-authored questions and multiple measures; their results distinguish correctness, coverage, relevance, and citation accuracy. Citation presence alone is insufficient, and too many retrieved passages can reduce quality in some configurations. | Supports #475's expert/source-grounded rubric: score whether cited passages support the complete premise and whether material counterevidence/coverage is handled, not whether an answer merely contains citations. This system covers a huge scientific corpus with specialized retrieval and models, unlike a fixed trial dossier; do not transplant its architecture or reported gain. |
| [OpenAI, Evaluate agent workflows](https://developers.openai.com/api/docs/guides/agent-evals) | The guide recommends trace grading to locate workflow-level failures, then datasets/eval runs for repeatable comparisons. | Use traces to classify retrieval, inspection, interpretation, and response-mapping failures, then test changes on frozen attempts/cases. Traces do not establish correctness, and this product guidance should not become an OpenAI-specific production dependency. |
| [McCleary & Ghawaly, BCAS, arXiv; accepted at LREC 2026](https://arxiv.org/abs/2603.08877) | A controlled, shared-scaffold study across six LLMs and three QA benchmarks found gains from additional searches up to a small cap, task-dependent benefit from larger output budgets, and retrieval/reranking effects. The paper reports that its shared prompt is not each model's best-case and its binary judge is only a proxy. | Strongest budget-design precedent for #463/#468: freeze and expose search/token budgets, retain per-attempt use, compare multiple model families, and measure accuracy before cost. Do not import its roughly-three-search result as a rob2-kit cap: corpora are static QA, outputs are short, full component ablations are on HotpotQA, and no result establishes safety for scientific assessment. |

## Narrow experiments supported by this review

1. **#475 → #476 (accuracy first):** build the adjudication set around the exact approved Result and source-located decisive premises. For each case, distinguish source availability, passage delivery, inspected Evidence, premise support/counterevidence, answer, and final deterministic label. Include all disagreements plus a predeclared sample of agreements; preserve defensible alternatives and indeterminate cases. This prevents tuning to catalog labels or citation presence.
2. **#474 (context only after adjudication is defined):** profile the complete current `get_domain_context` path, then compare one smaller complete delivery against it. Freeze the same questions, official qualifiers, Evidence identities, contrary evidence, and recovery routes. Primary outcome is adjudicated premise validity and unsupported reassurance/concern; bytes, calls, latency, and cost are secondary. Keep current delivery if scientific non-degradation is uncertain.
3. **#463/#468 (model-agnostic comparison):** compare supported model families under the same frozen cases, Source bytes, exact Results, tool contract, prompt, budget, draw policy, and scorer. Retain all runs. A shared-prompt comparison tests robustness to a common harness, not each model's ceiling; effort labels across vendors are not equivalent budgets.
4. **#473 (checkpoint handoff):** use the existing Result/source-bound checkpoint and document the rebind sequence after Proposal save. Verify changed Results/projections invalidate dependent notes and that exact Evidence remains recoverable. The repository already has the state machinery, so evidence here favors fixing the host handoff before adding another memory layer.
5. **Budget policy:** instrument search/context/cost now; lower a ceiling only after the accuracy-first comparisons show a material efficiency gain without scientific regression. Keep a visible path for continuing an unresolved material premise within declared limits. No-hit receipts and delivered context are not proof of absence or comprehension.
