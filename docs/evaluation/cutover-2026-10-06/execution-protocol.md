# Fixed ten-case execution protocol

This prospective operational test uses the unchanged ordered sample in
`ordered-sample.json`. It is not a held-out accuracy estimate. All cases were in
original Code benchmark evaluation; Albert and SUSTAIN have additional superseded
Low development exposure, and other later exposure is recorded per case or marked
unknown. Original human judgments and historical answers are excluded from model
inputs. No case is excluded, redrawn or replaced after failures.

Before inference, commit a final freeze receipt tying the reviewed candidate SHA,
installed wheel SHA, public tool contract and packaged skill hashes, exact CLI
model `gpt-6.1-sol` and reasoning `medium`, launcher/config hashes, and every
case's prompt, source boundaries, captured source identities, seed state, evidence
bundle and preflight manifest hashes. Implementation uses Sol Low; previous Low
pilots are a separate superseded stratum. A pending receipt is not launch approval.
Independent source/content, prose/schema and architecture/history reviews must
close on this exact candidate, with installed verification and regression results.

Use fresh isolated case workspaces and the native MCP source workflow. Preserve
original Code benchmark target wording, arms, endpoint, timing and effect measure.
Captured registry augmentation must be separately identified, hashed and disclosed;
no search or source replacement silently changes the original dossier boundary.
Preparation can freeze genuine native text and images but does not mark Sources
read. Empty text projections retain actual captured page pixels and a render action,
without invented text or a claim that the physical page is blank. Launch exclusively
through `diagnostic_evidence_preflight.launch_checked`; preserve failed checks.

The first attempt for each case is retained and assigned an explicit operational
terminal disposition. Proposal approval is scope-only after checking the original
target and source correspondence; give no Domain answers, preferred label or outcome
feedback. A same-session resume may repair transport/configuration failures or supply
scope-only approval. Record its reason and exact changes. General product bugs may
be corrected and retested in a separate version stratum after review; retain the
original run, failure and candidate identity. No label-driven rerun is permitted.

Supervise actual activity: no arbitrary total elapsed, token, tool-call or productive
reading limit. Stop on 300 seconds of actual idle with no active tool; allow an active
tool up to 660 seconds, with its 600-second transport timeout. Three identical failed
operations without intervening useful progress constitute a loop. Preserve exact
last activity, active operation, timeout/loop evidence and terminal reason. Native
render recovery and readonly Codex MCP metadata discovery remain technical actions.
Do not expose shell, web, outside skills or Astra to the assessment model.

After each process settles, seal inputs, logs, terminal receipt, usage, canonical
state and outputs. Verify every finalized bundle independently with both product and
standalone verifiers. Report operational completion, bundle integrity and scientific
assessment separately. Audit scientific judgments against inspected source passages,
complete official guidance and the exact target; distinguish defensible disagreement,
source conflict, unresolved scope and genuine failure. Matching imperfect reference
labels alone is not scientific success. Report all ten first attempts and every
resume/retest stratum, including failed and mixed results. No accuracy gain or merge
readiness claim precedes these gates; the full 106-case benchmark remains off.
