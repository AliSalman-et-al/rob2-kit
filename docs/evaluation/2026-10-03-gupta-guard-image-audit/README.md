## Guard repair

`scripts/workflow_completion.py:tool_feedback` now distinguishes native input-validation rejection, typed assessment rejection, explicit transport error (including its declared retryable flag), tool failure, conditions, researcher gates and successful results. It preserves the complete original event while constructing an equivalence key. Retained native Pydantic errors are recognized only from a complete first-line call-validation envelope matching the actual tool, positive count, and matching field-path/type-code entries. There is no general text-error regex and no 'missing structuredContent means error' rule. Typed successful source passages take precedence, and ordinary text/image success is retained.

For native input errors, equivalence uses tool, error kind, field paths and type codes: varying input excerpts, CRLF versusLF, event IDs, or failed-versus-completed envelopes do not defeat repeat counting. Original detailed messages, values and helpURLs remain in `ToolFeedback.original` and the unchanged traces. Typed assessment rejections retain their substantive details and ignore only volatile receipt heads/counters. Classification of an assessment repair is not an independent finding that the server's scientific judgment is correct. Retryability is taken from explicit transport metadata, never inferred from scientific source prose; no automatic retry or approval is added.

The actual `read_pages` error was a completed MCP item with `structured_content:null`, `error:null`, and a native call-validation message. The checkpoint-schema error had the same envelope. Both are now counted. Status-only recovery calls no longer clear a previous failure; a successful substantive tool call still clears it. Equivalent errors can therefore stop across resumed turns without swallowing legitimate successful image/text calls or crossing a researcher gate.

`bounded_launcher.py` is an **offline Budget replay**, with no process launch point. It applies the shared classifier to the preserved cumulative state: wall start, usage ledger, call IDs, turn count, error streak and prior details survive serialization and resume. Durable code-mode call IDs are counted once as wrappers in addition to MCP calls. Positive/negative tests replay the exact retained event, errors across turns and status reads, success resets, researcher boundaries, explicit transport retryability, normal images/text, and preserved output/tool/wall budgets. The original paid adapter and its strict expected-failure evidence remain unchanged; this code cannot reopen that run.

This is a demonstrated structured-content/image return seam. It supports the model's saved inability-to-inspect qualification; it is not a wrong-page request, absent source figure, corrupt PNG, lack of model image capability, or proof of poor interpretation despite visible pixels. Server/ImageContent delivery is distinct from sampler/model receipt.

## Narrow, opt-in compatibility entrypoint

`scripts/codex_mcp.py` runs the same rob2MCP server with image middleware only when explicitly chosen as the stdio entrypoint. It changes `render_page`'s advertised MCP output schema to optional/unstructured in that host path and, for successful image-bearing render results only, returns the **already validated JSON receipt in its existing text block beside unchanged PNG pixels**, omitting the duplicate structuredContent field that triggers the CLI shortcut. Other tool metadata and results remain structured; metadata-only renders and flagged errors are untouched. The normal `python -m rob2_kit.interfaces.cli.app mcp` server and public contract are unchanged.

For an authorized future Codex host configuration, the MCP command can use the existing Python interpreter with arguments pointing to `scripts/codex_mcp.py`, keeping the normal `ROB2_WORKSPACE` and`PYTHONPATH` setup. This compatibility path is deliberately opt-in rather than a hidden global behavior change. Clients in this path read the validated render JSON from TextContent and the image from ImageContent. No alternate evidence, synthesized visual description or operator scientific hint is injected.

Offline tests replay the exact retained PNG/receipt through FastMCP with and without middleware. The default retains structured metadata; the compatibility path advertises no required structured output and makes the exact image survive the version-matched CLI conversion branch. Inputs, metadata-only output, ordinary get_status, error flags and normal server tool schema remain compatible. A separate **actual stdio MCP** check against an operator-only workspace returned the identical PNG with its validated text receipt and left get_status structured; `stdio-replay.json` preserves the receipt. None of this proves model comprehension after a future launch.
