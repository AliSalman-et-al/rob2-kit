# Generalized account construction and structural repair

Trace item14 used a steps wrapper; item15 corrected only structure; item16 shortened
observations and removed “Assessor blinding to group not stated.” The initial
exact draft remains in immutable native events/rejections. structural-repair-review.json
is generated from those existing receipts, including every exact attempted request,
error/receipt and changed or removed scientific content. The helper diagnoses;
it neither validates a malformed shape nor merges rejected facts into an account.

Previously account observations required locator copying while Domain bases
accepted selected handles/text ranges/delivered visual transcriptions. Account
inputs now use the same DomainSourceReference and existing selector resolver.
The single result_account array shape remains. Existing locator inputs remain for
compatibility; there is no steps alias or new MCP tool. Native tool schema,
description and read_guidance carry the reference forms and a neutral handle-based
example. Stored WorkingNote/WorkingResultStep shape remains source-located;
selected visual evidence retains its original render, source, region, transcription,
uncertainty and delivered-image provenance in the existing evidence store.
Canonical history and answer rules are unchanged. Legacy whole-page notes remain
valid; explicit visual references require a genuine current-Trial receipt.

Unknowns, optional inference, counterevidence and source scope are retained exactly
as supplied, not inferred. Empty values remain valid. Diagnostic comparison makes
removed/changed content reviewable to the supervisor using existing native receipts;
it is not an automatic in-assessment warning or a rejected-draft persistence ledger.
The host can already inspect its attempted requests. Guidance asks it to reconsider
content changes during repair, without forcing retention. No behavioral gain has
been tested and no rejected scientific content is silently recovered.
