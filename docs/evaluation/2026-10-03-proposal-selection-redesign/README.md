# One scientific Trial selection replaces duplicate public records

Offline implementation, no paid inference. Source of evidence: the actual two EMPEROR recovery requests from the required Code benchmark, the current native tool declaration, current bundled/exported workflow, and unchanged application/canonical validators. Defect inventory records every one of the remaining 7/25 defects by group and raw count. Historical artifacts are not edited.

## Defect inventory

Request 1: one malformed clarity declaration; numeric estimate/precision objects instead of source strings; narrative prose in optional advanced Evidence; repeated evidence-basis prose instead of selected handles; unknowns as a dictionary; counterevidence as prose. Request 2: eight undeclared clarity facets; two group values placed in the statistic field while value is absent; three selected handles duplicated as advanced proof objects; eleven missing candidate fields and one forbidden missing_facts field caused by creating a second Result for unresolved facts. Exactness alongside unresolved endpoint-criteria facts is a separate scientific calibration issue, not an extra counted syntax defect. No source absence or desired scope relation is inferred from construction errors.

## Before / after

Before: validate_proposal(results, assessments, expected_revision, missing_results=[]). The caller coordinates three collections, repeats Trial identity and supporting handle lists, and supplies overlapping relation rationale / scope justification.

After: validate_proposal(selections, expected_revision). Each selection has trial_id, explicit relation, candidate or null, scope_rationale, population_rationale, source_passages, unknowns and counterevidence. A null candidate requires source-grounded missing_facts. A complete candidate cannot also carry missing_facts; unknown facts remain in unknowns. There is one selection per Trial, with the existing duplicate-Trial gate. No canonical record kind/form/timing tags or separate reasoning record are submitted.

The server copies the same explicit scope rationale into canonical relation rationale and reasoning scope justification, and reuses the same explicit passage set for Result evidence and reasoning evidence basis. It does not decide whether those passages entail the claims. Design-specific citations stay separate. Advanced table/multispan/derived proofs stay typed because they encode scientific mappings rather than known handle metadata. The replacement public models have no old-shape alias, parallel branch or compatibility parser. Package and contract version advance to 0.11.0; the project lock only changes its local project version, not dependencies.

## Minimal scientific content and limits

For one reported comparative candidate, the host must still supply source-supported design with its citations; target measurement, window, randomized groups, baseline-defined subgroup or null, and intended effect measure; reported endpoint/definition when supported, analysis population and faithful estimate/precision strings or complete paired values with units; explicit relation and a source-based scope rationale; population reasoning separating eligibility, exclusions and outcome availability; source passages, material unknowns and counterclaims. Exact additionally requires all eight clarity facets explicitly specified. A correct HR is insufficient.

The server derives only record tags, timing representation from paired quantities, captured requested outcome/metric, assignment effect, target population from the explicit subgroup, retained evidence kind/identity/coordinates and validated numerical bindings. It cannot safely derive endpoint semantics, relation, missing measurements, source units, analysis exclusions or scientific clarity. Those obligations remain. Numeric objects and unknown-field dictionaries are not coerced. No universal call was added; validation/save and Proposal Review retain their existing roles. Scientific repairs and scope review retain canonical scientific paths; they are not a requirement to construct internal records.

This removes demonstrated record-coordination complexity rather than adding another recovery instruction or nullable metadata field. It does not resolve all EMPEROR scientific gaps or the unread main-report page 10 lines 17–202. Unchanged raw requests are rejected as retired v0.10 input, not silently repaired; unchanged-request-replays.json preserves their hashes. Authored current-schema source-bound controls separately establish actual construction, saving and scope-gate behavior; they are not repaired model runs or expert reference labels.
