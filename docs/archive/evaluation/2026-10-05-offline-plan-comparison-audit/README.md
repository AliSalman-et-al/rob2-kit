# Bounded offline plan-comparison audit

**No new production feature or guidance is justified by this audit.** Existing comparison cards, optional premise records and source guide already support source-located planned/reported content, original/amended plans, calculation scope and chronology as separate propositions. The four actual Code benchmark traces show mixed delivery/interpretation limits and useful counterexamples. They do not establish a recurring server defect or a missing capability. No paid call, ASCET retry, benchmark rerun, reset or source mutation occurred.

Scope: original October1 Code benchmark traces for CANVAS, PIONEER-6, EMPEROR-Reduced and DAPA-HF, selected for multiple-plan handling and counterexamples. Original accepted D5 submissions and completed structured read/search/context bodies were inspected; references/scores were not used as authority. Code trace and source hashes are preserved. Current implementation structures are recorded in existing-structures.json. Historical traces used older generic comparison-card wording; they are not an evaluation of the later detailed content-comparison prompt. The recent PIONEER mechanism test supplied source text/question guidance, not native comparison cards.

This is a declared-window audit, not an exhaustive reading map or scientific sufficiency test.

DAPA supplies a useful metadata control: physical223 has an ANGEL form header mentioning4.0 alongside the trial SAP's Edition3.0 dated23July2019. Amendment230–231 and signature275 corroborate the trial edition3; the signature records24July approval. A naive automatic version parser could create a false contradiction. Header/title, document-management version and scientific-plan edition must be interpreted in source context; no version parser or case-specific rule is added.

Why no feature: current cards already compare exact target/reported scope and planned calculation with citations, timing and reasons; source groups expose combined documents even with empty selected passages. Source guidance distinguishes content, applicability, finalization, access and prospective intent versus actual conduct, and already permits probable inference. Host-owned premise records can retain observations, inference, counterevidence and unknowns without another schema or mandatory checklist. A passage gap can arise from discovery/host stopping rather than a server omission. A supplied passage can still be omitted from a rationale. CANVAS and the old PIONEER mechanism response show relevant behavior can work. The evidence does not isolate a recurring remediable transport/organization defect.

**Strongest remaining hypothesis:** host reasoning sometimes compresses calculation-level correspondence into matching endpoint, population and model labels, or treats a planned safeguard as stronger conduct evidence than warranted. First test this offline with source-aware review of material planned/reported changes and unchanged/irrelevant-change controls using existing source groups/premise records. Distinguish whether the passage was available, delivered, compared and scientifically material; a detail absent from prose is not automatically a bias error. If existing tools repeatedly deliver/represent needed evidence poorly, simplify that concrete path; if they deliver it but inference fails, address that semantic distinction without mandatory dates, forced labels or a new judgment framework. No future paid launch is specified here.

Authority remains Cochrane2019 §1.1, §8.3.1 and Box11: reasonable probable inference is permitted; compare plan with actual analysis and weigh changes/timing/reasons, rather than treating every amendment as bias. [Full guidance](https://www.cochrane.de/sites/cochrane.de/files/uploads/RoB_2.0_guidance_2019.pdf). No judgment/reference is silently repaired and no accuracy gain is claimed.

Full benchmark remains off.
