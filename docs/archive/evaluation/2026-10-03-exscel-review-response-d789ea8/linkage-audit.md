## Implemented change: private diagnostic preflight only

There is insufficient evidence for another production source-link/recovery feature. Existing passage handles and expansions already supply the necessary mechanism. The narrow change is `scripts/diagnostic_evidence_preflight.py` and a repository instruction requiring its `launch_checked` entry point for every future paid short scientific diagnostic.

An investigator freezes the research question, required source identities and page/line windows, exact input hash and supplied-source byte spans/hashes. The checker requires every declared window to be covered by the same source/page, verifies frozen input and passage hashes, and rejects gaps. It does not inspect prose for keywords, infer semantic relevance, autoattach pages, inject expected answers, or add production assessment fields. Requirements stay private; only evidence belongs in model input. The checker cannot detect a requirement the researcher failed to declare, so primary-source/design inspection remains necessary before freezing the manifest.

`launch_checked` checks before subprocess creation and writes a hash-bound successful receipt before launch. Tests prove an omission causes no child process or success receipt, contiguous coverage succeeds, gaps/wrong source/wrong page/changed input/corrupt passage fail, and the actual confounded EXSCEL input is rejected when page 188 lines 20–40 is explicitly required. A retrospective manifest and failure receipt reproduce this rejection without inference; they are clearly marked retrospective and never rewrite the original preregistration.
