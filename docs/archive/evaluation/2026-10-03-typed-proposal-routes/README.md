The EMPEROR primary-report trace extracted HR 0.75 and CI 0.65–0.86 correctly but exhausted its allowance constructing a proposal. Its former undiscriminated Result/MissingResult union returned 13–16 irrelevant missing-record branch errors per attempt. This checkpoint changes construction, not scientific judgment or outcome accuracy.

## Public contract

`validate_proposal(results: ResultProposal[], assessments: ProposalReasoningAssessment[], expected_revision, missing_results: MissingResultProposal[] = [])` uses two homogeneous record collections. Missing-only submissions use `results: []`. Both feed the same atomic application validation and unchanged save receipt. Server conversion derives canonical available/unavailable tags; it does not infer relation, target scope, analysis population, design or scientific sufficiency.

Simple narrative/figure evidence uses selected `passage_refs` strings; the server derives known evidence kind and source metadata. Explicit table, multispan and derived proofs remain typed in `evidence`. Arm assignment remains explicit `{id, assignment}` because selected passage handles do not supply an authoritative structured arm catalog. Canonical storage, IDs, approval, export and historical descriptor verification are unchanged.

Invalid public construction returns chosen-collection fields, at most eight defects, an additional-defect count, and at most 4096 UTF-8 bytes. Recovery guidance gives exact field structure, not source answers or hints to change scientific conclusions. Missing-only feedback contains missing-record guidance. Well-shaped unknown handles and semantic/source requirements still reach application validation.
