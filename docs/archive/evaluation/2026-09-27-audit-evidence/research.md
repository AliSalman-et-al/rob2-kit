# Agent and RoB 2 design research

Scope: focused source review to inform the 2026-09-26/27 eval audit. Recommendations below are conditional on the gaps demonstrated by those traces; they are not a proposal to rebuild already-present infrastructure.

## Directly relevant scientific guidance

- **RoB 2 is result-specific and evidence-backed.** The assessment concerns a specific result; each signalling answer and judgement needs a written justification, and questions should be answered independently except for skip logic. The response `No information` has a narrower definition than “the model is unsure”: use it only when reporting is insufficient and trial circumstances do not support either probable answer. [Cochrane Handbook, Ch. 8](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-08)
- **D3.2 means evidence of no bias, not a demand to prove bias.** The official RoB 2 guidance asks, “Is there evidence that the result was not biased by missing outcome data?” It identifies bias-correcting analysis methods and sensitivity analyses over plausible missingness assumptions as evidence supporting Yes/Probably yes. If such evidence is absent, No/Probably no is the answer path; that alone does not establish bias. Q3.3 then asks whether missingness *could* depend on the true outcome, and Q3.4 asks whether that dependence is *likely*. The official mapping gives Low for D3 when there is evidence of no bias (or missingness could not depend on the true value); when data are not nearly complete and Q3.2 evidence is absent, subsequent Q3.3/Q3.4 determine Some concerns versus High. This is a useful error check for conflating “no evidence of unbiasedness” with “evidence of bias.” [Official RoB 2 guidance, pp. 44–46](https://www.riskofbias.info/welcome/rob-2-0-tool/current-version-of-rob-2) (same guidance PDF hosted by Cochrane Germany: [PDF](https://www.cochrane.de/sites/cochrane.de/files/uploads/RoB_2.0_guidance_2019.pdf), see lines for Q3.2 and Table 10)
- **Overall multiple Some concerns requires a material combined-confidence judgment in the general guidance.** Cochrane’s overall criteria say High when any domain is High, or when Some concerns in multiple domains “substantially lowers confidence in the result.” This does not itself declare a numeric threshold of two. Repository ADR 0035 expressly freezes the deterministic `>=2 Some concerns => High` convention for the current repair program so assessments remain comparable; any change requires a separate explicit decision. Keep the current rule in this work and report it separately from domain accuracy. [Cochrane Handbook, Ch. 8](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-08), [ADR 0035](../../adr/0035-retain-current-overall-aggregation.md)

## Agent workflow evidence and what it implies here

- **Reason and act on observations.** ReAct research supports interleaving task reasoning with external actions and their observations for knowledge-intensive QA/fact verification; it does not show that an unconstrained or fixed number of calls is optimal. For this repo, evaluate whether traces show the model stopping after a search snippet, failing to inspect relevant pages, not following an expansion/recovery path, or failing to revise a draft after new evidence. [ReAct paper](https://arxiv.org/abs/2210.03629)
- **Improve tool use only where traces demonstrate friction.** Tool-design guidance recommends observing raw traces and measuring redundant calls, parameter errors, tokens, latency, and correctness; it cautions against adding more overlapping tools. MCP schemas/results can carry typed structured content, but the protocol is not evidence that a new tool itself improves answer quality. [Anthropic tool design](https://www.anthropic.com/engineering/writing-tools-for-agents), [MCP tool spec](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)
- **Context should be a focused projection, not accumulated transcript.** Long agent loops need selection of the information passed on each turn; just-in-time retrieval may save context but adds runtime and depends on good existing navigation tools. Here `search_sources`, `search_sources_batch`, `read_pages`, `render_page`, evidence selection, and durable working checkpoints already exist (see [CONTEXT.md](../../../CONTEXT.md)). Do not add `extract_table` or another retrieval tool just because tool design sources discuss tool ergonomics. First identify a repeated table-specific gap in the eval traces and quantify whether current `read_pages`/render paths fail to surface the needed table evidence; then prototype/ablate the smallest change. [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), [repo context and tool inventory](../../../CONTEXT.md)
- **Score stages, then compare models.** Trace-based evaluation can localize tool selection and workflow failures; repeatable datasets support controlled comparisons. First hold the model fixed and ablate a demonstrated infrastructure/context issue. Separately hold the agent/tool path fixed while comparing model families and reasoning effort. Evaluate question-level answer accuracy, evidence/premise support, tool-call errors, completion, cost, latency, and repeated-run variability. Higher reasoning is a hypothesis to test on these specific failure classes, not a presumed remedy. [OpenAI agent eval guide](https://developers.openai.com/api/docs/guides/agent-evals), [OpenAI reasoning guidance](https://developers.openai.com/api/docs/guides/reasoning)

## Design constraints for recommendations

1. Treat labels as provisional references: inspect approved Result, source passage, answer basis, and guidance before calling a deviation a model error. Cochrane permits overrides of suggested algorithms with reasons; benchmark agreement is therefore not itself scientific correctness.
2. Keep the proposed changes model-agnostic. Prefer exact evidence references, typed state, and deterministic scoring of observable behavior over model-specific prompt tricks or private chain-of-thought assumptions.
3. Do not infer a model ceiling from one Luna Medium run. Split extraction/retrieval/interpretation/algorithm failures before deciding whether larger models or more reasoning effort could help.
4. Preserve the accepted ADR 0035 overall aggregation in this work. The combination judgment may merit a separate scientific policy discussion, but it is not a casual benchmark-optimization lever.
