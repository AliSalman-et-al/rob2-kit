# Run-definition reference

Use this reference only while the Run is unconfirmed or when the operator asks
to change its scope. The engine-issued proposal remains the authoritative
record.

Start by preparing the explicitly selected project root. Inspect and classify
only Sources issued in the current work context, then resolve one issued Result
at a time. Keep each proposed Result tied to its Trial, Randomization,
Comparison, outcome definition and measurement, analysis, time point, effect
measure, result-bearing Source locator, and visible limitations.

Present the compact proposal in plain language. A requested Trial × Outcome
target must be selected, excluded with a readable reason, or explicitly
removed by the operator. Material identity, outcome, analysis, or time-policy
ambiguity remains a decision; do not fill it from file names, abbreviations,
citations, or general knowledge.

When the operator corrects scope, submit the supported correction as a complete
successor proposal and show the returned semantic difference. Confirm only the
latest proposal token with the attributable human actor returned by the
workflow. Confirmation authorizes preparation; it does not approve findings or
reports. Once confirmed, return control to `rob2-assess`.
