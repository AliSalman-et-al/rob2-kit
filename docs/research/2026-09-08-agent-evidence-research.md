# Agent evidence retrieval and context workflow research

Date: 2026-09-08

This note is tailored to `rob2-kit` as described in [`CONTEXT.md`](../../CONTEXT.md): a model-free FastMCP boundary in which the server owns source capture, Evidence identity, state, validation, deterministic RoB 2 logic, and artifact export, while the host owns scientific interpretation. It records evidence from primary sources and separates recommendations from claims established by those sources. None of the reported gains below is evidence of a gain on this repository's trial corpus.

## Findings from the full Pi-Serini paper

The primary paper is Hsu, Yang, and Lin, “Rethinking Agentic Search with Pi-Serini: Is Lexical Retrieval Sufficient?” ([arXiv abstract](https://arxiv.org/abs/2605.10848); [full main paper and appendices](https://arxiv.org/html/2605.10848v1)). I read Sections 1–9 and Appendix A–C before consulting the implementation documentation.

**Source-supported.** Pi-Serini isolates agent–retriever interaction behind a constrained retrieval controller. It separates lexical retrieval, browsing a cached ranking, and selective document reading. Search caches up to 1,000 ranked documents under a session identifier and initially exposes only five excerpts; browsing paginates that ranking, and document reading paginates line ranges. This lets retrieval depth grow without placing the whole ranking in the model context (paper Sections 3.1–3.2, [lines 101–131](https://arxiv.org/html/2605.10848v1#S3)).

**Source-supported.** The paper logs four different document sets: surfaced by the system, previewed by the agent, opened through document reading, and cited in the answer. It therefore distinguishes availability, inspection, opening, and final use rather than treating one retrieval result list as the whole workflow (Section 3.2, [lines 132–151](https://arxiv.org/html/2605.10848v1#S3.SS2)).

**Source-supported.** On BrowseComp-Plus (830 queries and 100,195 documents), the reported gpt-5.5 Pi-Serini run reached 83.1% answer accuracy and 94.7% surfaced evidence recall. These are benchmark-specific results, not clinical-evidence validation (Sections 4.1 and 5, [lines 160–190](https://arxiv.org/html/2605.10848v1#S4.SS1), [lines 232–247](https://arxiv.org/html/2605.10848v1#S5)).

**Source-supported.** Retrieval depth and first-stage configuration mattered substantially in the paper's ablations. For gpt-5.4, increasing depth from 5 to 100 raised surfaced recall from 70.5% to 86.22%, and depth 1,000 reached 95.8%; previewed recall saturated around depth 50–100. On a 100-query subset, tuning BM25 from `(k1=0.9,b=0.4)` to `(25,1)` increased reported accuracy from 64.0% to 82.0% and surfaced recall from 84.6% to 95.7% (Section 6, [lines 278–293](https://arxiv.org/html/2605.10848v1#S6)). The authors explicitly attribute the result to long, noisy documents and caution that the conclusion is about this benchmark.

**Source-supported.** The study also reports a gap between surfaced and previewed/behavior recall. More candidates being available did not automatically make the agent inspect or use them. Its discussion identifies premature branch commitment: after a weak candidate is introduced, an agent may keep searching within that branch instead of returning to the original constraints (Sections 5 and 7, [lines 242–247](https://arxiv.org/html/2605.10848v1#S5.SS2), [lines 316–320](https://arxiv.org/html/2605.10848v1#S7)).

**Source-supported limitation.** The paper says its interface remains minimal, previewed and behavior recall are substantially below surfaced recall, and generalization to multilingual and domain-specific settings is open. It also notes that a fixed time budget can under-explore difficult queries or over-spend on easy ones (Section 9, [lines 332–335](https://arxiv.org/html/2605.10848v1#S9)).

**Inference for `rob2-kit`.** The existing `search_sources` → `read_pages` → exact Evidence selection boundary already matches the strongest transferable interaction pattern. The practical work is to make the disposable retrieval controller retain a deep, Trial-scoped ranking while returning bounded previews, stable cursors, and executable recovery. Do not copy Pi-Serini's BM25 parameters or 1,000-document depth without a held-out RoB 2 retrieval evaluation. Measure at least: needed-passage surfaced recall, previewed recall, exact Evidence selection/use, rank pagination, query reformulation, repeated/novel candidate yield, and cost/latency.

**Inference for `rob2-kit`.** A query/accounting record should distinguish “candidate surfaced,” “passage previewed,” “page opened,” and “Evidence used in a checkpoint.” This complements the repository's immutable Evidence and checkpoint records; it must not turn a search hit or a no-hit receipt into a scientific absence claim. A query-specific, bounded “return to root constraints” recovery hint may help with premature branch commitment, but it should be retrieval advice and never a server-authored scientific conclusion.

## MCP and agent-tool guidance

**Source-supported.** The MCP Tools specification says tools are model-controlled, but recommends a human in the loop with visibility and the ability to deny invocations. It requires valid input schemas; servers may provide output schemas, and when they do, structured results must conform while clients should validate them. Structured results should also have serialized text for compatibility ([MCP Tools specification](https://modelcontextprotocol.io/specification/draft/server/tools), especially the [user interaction](https://modelcontextprotocol.io/specification/draft/server/tools#user-interaction-model), [tool](https://modelcontextprotocol.io/specification/draft/server/tools#tool), and [structured content](https://modelcontextprotocol.io/specification/draft/server/tools#structured-content) sections).

**Source-supported.** MCP recommends deterministic tool ordering because clients can cache the tool list and improve prompt-cache hit rates. Its annotations are untrusted hints and must not substitute for enforcement ([MCP Tools specification](https://modelcontextprotocol.io/specification/draft/server/tools#capabilities), [tool annotations](https://modelcontextprotocol.io/specification/draft/server/tools#tool-annotations)).

**Source-supported.** Anthropic's first-party guidance recommends starting with the simplest system, keeping workflows predictable for well-defined tasks, giving agents environmental ground truth at each step, and adding complexity only when evaluation shows it helps. It describes evaluator–optimizer loops as appropriate when evaluation criteria are clear and iteration produces measurable improvement ([Building effective agents](https://www.anthropic.com/engineering/building-effective-agents), Sections “When (and when not) to use agents,” “Agents,” and “Evaluator-optimizer”).

**Source-supported.** Anthropic's tool guidance treats tool descriptions as part of the agent-computer interface: descriptions should explain examples, edge cases, input requirements, and boundaries; parameters should make mistakes difficult; and tool behavior should be tested across many example inputs ([Writing effective tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents), Appendix 2 of [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)).

**Inference for `rob2-kit`.** Keep the 14-tool boundary and deterministic server enforcement. Improve descriptions and schemas only where they reduce a demonstrated repair failure: state the exact lexical mode, Trial/Domain scope, cursor semantics, Evidence authority, and which fields are server-owned. Preserve `get_domain_context` as the bounded recovery projection, with stable ordering and canonical state first. Use MCP annotations for client UX only; authority, optimistic concurrency, idempotency, and active-question validation stay server-enforced.

**Inference for evaluation.** Treat “tool call was valid,” “tool returned the needed passage,” “model selected exact Evidence,” and “scientific answer/judgment was correct” as separate criteria. A final-judgment score alone cannot identify whether a miss came from retrieval, context allocation, interpretation, or deterministic logic. A development evaluator–optimizer loop is reasonable only after these criteria and expert ground truth exist; it should not become a second authority path.

## Cochrane / RoB 2 domain reasoning

**Source-supported.** The Cochrane Handbook identifies RoB 2 as the recommended tool for randomized trials and describes it as a framework for assessing risk of bias in a single result. The official RoB 2 site identifies the current individually randomized parallel-group version as the 22 August 2019 tool and provides its full guidance and templates ([Cochrane Handbook Chapter 8](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-08); [official RoB 2 tool site](https://www.riskofbias.info/welcome/rob-2-0-tool/current-version-of-rob-2)).

**Source-supported.** The RoB 2 framework is result-specific: the object is a particular intervention-effect estimate for a particular outcome, with judgments supported by signaling-question answers and evidence. The original tool paper describes the framework as assessing risk of bias in a single estimate of an intervention effect from a randomized trial ([BMJ RoB 2 paper](https://www.bmj.com/content/366/bmj.l4898)).

**Inference for `rob2-kit`.** Retrieval should be driven by the approved Result target and active question semantics, then broadened question-by-question when a premise is missing. The current design is scientifically aligned when it keeps endpoint definitions, timing, population, effect measure, arm assignments, reported labels/values, and exact supporting passages distinct. Plans, labels, relationship terms, and a prior Result Evidence set must not be treated as proof of conduct, measurement properties, prespecification, or exhaustive source review.

**Inference for context design.** Every active answer should expose (or provide exact recovery for) the source passage, page/line coordinates, the relevant question and branch, and whether the basis is Evidence, a scoped absence receipt, or an explicit limitation. This supports auditable reasoning while retaining the repository's rule that the server derives canonical quoted text from selected Evidence and stores only the official RoB 2 answer.

## Recommended next experiments

These are hypotheses to test on a held-out, expert-reviewed RoB 2 corpus, not established gains:

1. Compare current retrieval depth with deeper cached rankings while holding capture, projection, model, and Evidence authority fixed.
2. Measure retrieval and context-allocation tiers separately for each Domain and Source role; include exact Evidence-use rate and contradiction discovery.
3. Test question-scoped query suggestions and reversible root-constraint reminders against the current operational guidance, with no change to scientific judgment logic.
4. Test deterministic context reconstruction after simulated restart/compaction and verify that identical canonical state yields identical ordering, cursors, and Evidence recovery.
5. Use at least two model families and repeated development runs; report dispersion and failure categories, while preserving the repository's one-attempt release qualification rule.

## Whole-paper context versus retrieval: bounded experiment

The comparison below records the original research proposal. The required product workflow in [#300](https://github.com/AliSalman-et-al/rob2-kit/issues/300) was subsequently changed to two mandatory bounded text passes, with a 64 KiB ceiling per report and explicit partial coverage. That product decision is not evidence of an accuracy gain; the research comparison remains useful for evaluating context allocation.

The full Pi-Serini paper does not test “put the entire document in context” against its cached-ranking interface. Its direct comparison is architectural: it argues that shallow retrieval which inserts full texts conflates retrieval depth with context management, then evaluates a controller that caches a deep ranking while exposing small previews and paginated reads ([Section 3.2](https://arxiv.org/html/2605.10848v1#S3.SS2), lines 117–131). The paper's results show surfaced recall continuing to improve at depth 1,000 while previewed recall saturates much earlier ([Section 6](https://arxiv.org/html/2605.10848v1#S6), lines 278–285). This supports separating candidate availability from context allocation; it does not establish that whole-paper context is inferior for trial reports.

The paper's own limitation is relevant: previewed and behavior recall remain well below surfaced recall, and fixed time budgets may under-explore difficult queries ([Section 9](https://arxiv.org/html/2605.10848v1#S9), lines 332–335). A bounded `rob2-kit` experiment should therefore compare strategies on the same captured Sources, projection, approved Result, model, and wall-clock/token budget:

1. **Whole-main-paper condition:** provide the complete authoritative text of one designated main report, with page markers, and allow the model to answer the Result and Domain questions without lexical search. If the report exceeds a pre-registered context budget, record truncation rather than silently summarizing it.
2. **Retrieval condition:** use the existing deep cache/cursor workflow; expose the same report through bounded search previews, `read_pages`, and exact Evidence selection. Keep retrieval depth and preview limits fixed for the run and log all surfaced, previewed, opened, and checkpoint-used passages.
3. **Hybrid condition:** provide a small fixed front matter (title, abstract, contents, and Result scope) plus the retrieval condition. This tests whether upfront orientation helps navigation without paying for the whole paper.
4. Score independently: active-question premise recall, exact Evidence grounding, unsupported-premise rate, contradiction handling, answer/judgment agreement with blinded expert references, context tokens, searches/cursor continuations, latency, and failure to complete. Stratify by paper length, table density, Source role, and Domain.
5. Use a blocked split by Trial so protocol, report, supplement, and related documents cannot leak across conditions. Repeat runs for development variance, and pre-register a rule that no condition is preferred unless it improves the primary grounding metric without a material safety or audit regression.

This is a practical bounded experiment, not a recommendation to add a whole-paper mode to the public boundary. The existing deep cache and cursors are already sufficient to run the retrieval arm; only an evaluation harness needs to materialize the whole-paper and hybrid projections.

## RoB 2 audit of the reported NI patterns

The official 22 August 2019 guidance is available from the [RoB 2 source page](https://www.riskofbias.info/welcome/rob-2-0-tool/current-version-of-rob-2), which links the [full guidance PDF](https://drive.google.com/file/d/19R9savfPdCHC8XLz2iiMvL_71lPJERWK/view?usp=drive_open). The statements below use the official signaling-question wording and proposed-judgment tables; those tables are defaults that assessors may override with a justified scientific judgment.

**D1 allocation concealment (1.2).** The official question allows Yes/Probably yes for remote or central allocation and appropriately used envelopes/containers; No/Probably no when the enrolling investigator or participant could know the forthcoming allocation; and No information when reporting is insufficient. Crucially, the guidance says that sparse details may justify Probably yes or Probably no in context, rather than forcing No information. Its default table maps unknown concealment plus baseline imbalance to High, and unknown concealment with no/problem-free baseline information to Some concerns ([guidance pp. 17–20](https://www.riskofbias.info/welcome/rob-2-0-tool/current-version-of-rob-2)). Therefore the reported 31 D1 concealment NI cases are not by themselves evidence of an overly strict framework or a reason to force Low. Audit whether the agents distinguish “only randomized/central registration/sequence number” from a genuinely informative but incomplete concealment description, where Probably yes or Probably no can be defensible.

**D2.3 trial-context deviations.** The official guidance says Yes/Probably yes requires evidence or a strong reason that trial recruitment, engagement, or personnel led to failure to implement protocol interventions or to implementing non-protocol interventions. Ordinary non-adherence, participant stopping, and protocol-consistent changes should receive No/Probably no; No information is appropriate when the report does not say whether the trial context caused the deviation ([guidance p. 28](https://www.riskofbias.info/welcome/rob-2-0-tool/current-version-of-rob-2)). `scientific.py` preserves this distinction, including the explicit No information option and the invalid shortcuts “nonadherence alone” and “a protocol deviation without its cause.” No concrete deviation was found here. A high NI rate would be scientifically plausible when reports omit causal context; reducing it by inference would risk turning ordinary deviations into context-caused bias.

**D3.3 and D3.4 missing outcome data.** Official 3.3 asks whether missingness *could* depend on the true value; 3.4 asks whether it is *likely* to have depended on it. Official 3.4 explicitly distinguishes Some concerns from High and lists five Yes reasons: between-group missingness/censoring differences, reasons evidencing dependence, reasons differing by group, trial circumstances, and censoring after stopping/changing intervention. It allows No when analysis accounts for relevant participant characteristics, and No information when likelihood cannot be judged ([guidance pp. 45–48](https://www.riskofbias.info/welcome/rob-2-0-tool/current-version-of-rob-2)). Thus the reported 24 D3.4 NI of 69 is not automatically an error or a prompt to assign Low. The implementation's `likely-dependent` guidance and evaluator map NI to High when the question is active, matching the official proposed table's conservative default; review cases where NI was used despite one of the five concrete Yes/No patterns being present.

**Concrete operational strictness to investigate.** The domain prompt requires bounded searches “for every active question” before the first save, and says not to write a limitation or No information answer from selected Result Evidence alone. That is a defensible evidence-retrieval control, but it is stricter than the official tool, which specifies what information supports each answer and permits context-based Probably judgments; it does not prescribe a search count or cursor use. The observed 8 cursor searches out of 1,854 calls therefore indicates an agent-behavior or instrumentation question, not evidence that the cursor feature is missing. Add per-question telemetry for search attempts, cursor continuation, candidate novelty, and final basis type, then inspect whether cursor continuation was unnecessary, undiscovered by the host, or blocked by overly small previews. Do not relax the requirement merely to reduce NI, and do not force Low when the official information standard is unmet.

## Scope and limitations

Pi-Serini's numerical findings come from BrowseComp-Plus and its particular corpus, models, judge, timeout, and implementation. MCP and Anthropic documents specify interface and engineering practices, not medical or scientific accuracy. Cochrane sources define the RoB 2 reasoning authority, not an optimal retrieval algorithm. All `rob2-kit` recommendations above are therefore testable design hypotheses unless explicitly marked source-supported.

## Additional primary research relevant to the observed traces

### Long context is useful but position- and budget-sensitive

**Source-supported.** Li et al.'s EMNLP Industry Track study compares standard RAG and long-context (LC) prompting across public datasets and three models evaluated in the paper, then evaluates a Self-Route policy that routes between RAG and LC using model self-reflection. The authors report that sufficiently resourced LC often has higher average task performance, while RAG has a substantial cost advantage; Self-Route retains comparable performance at lower computation cost ([ACL paper and full PDF](https://aclanthology.org/2024.emnlp-industry.66/)). This is the strongest direct evidence here for testing a hybrid condition, but its datasets and tasks are general QA/summarization rather than trial-report RoB 2.

**Source-supported.** Liu et al.'s controlled multi-document QA and key-value experiments vary context length and the position of the relevant item. They find a U-shaped position effect: models use information best near the beginning or end and worse in the middle, including long-context models. In a NaturalQuestions-Open case study, model performance saturated well before retriever recall, with only marginal gains from 20 to 50 retrieved documents ([TACL full paper](https://direct.mit.edu/tacl/article/doi/10.1162/tacl_a_00638/119630/Lost-in-the-Middle-How-Language-Models-Use-Long)).

**Inference for `rob2-kit`.** A Krolewiecki run missing the randomization section on main page 4 while an r89 run retrieved and cited it is consistent with a retrieval/context allocation failure, but the trace alone cannot distinguish lexical miss, rank depth, page-preview placement, or model choice. If the whole main paper is supplied, randomize the relevant passage's position and preserve page markers; if retrieval is used, compare whether the passage was surfaced, previewed, opened, and selected. Keep exact Evidence coordinates as the authority.

### Query reformulation can help, but naive rewriting can hurt

**Source-supported.** The BRIGHT benchmark paper evaluates retrieval for difficult, reasoning-intensive queries across diverse domains. It reports that using LLM-generated reasoning steps as queries improves BM25 retrieval, with GPT-4-generated reasoning queries producing the strongest BM25 results in the reported comparison; conventional cross-encoder reranking trained on MS MARCO sometimes degrades performance, while LLM reranking helps but remains dependent on first-stage retrieval ([BRIGHT full paper](https://arxiv.org/pdf/2407.12883)). The benchmark's best scores remain low, so it demonstrates headroom and a useful evaluation setup rather than a universal reformulation recipe.

**Source-supported limitation.** Iterative conversational reformulation results are mixed. IterCQR trains reformulation against IR reward and reports gains on conversational-search datasets for sparse and dense retrievers, whereas the CAsT mixed-initiative study finds some feedback/rewrite methods improve retrieval and others substantially reduce nDCG; over-rewriting and feedback with no useful clarification are identified failure modes ([IterCQR](https://arxiv.org/abs/2311.09820); [Mixed-initiative Query Rewriting](https://arxiv.org/abs/2307.08803)). Neither study is a clinical evidence corpus.

**Inference for `rob2-kit`.** With 1,854 searches and 645 no-hit results, broadening every query or adding model-generated synonyms is not justified. First classify exact repeats, no-hit retries, changed lexical modes, and whether a query added new Source/passage identities. Evaluate a small, question-card vocabulary expansion against the existing lexical modes; retain the original query and its receipt, and never treat a widened query or no-hit receipt as evidence of absence. The current deterministic any/phrase/all/prefix boundary is an appropriate control.

### Retrieval does not guarantee evidence synthesis

**Source-supported.** The OpenScholar study evaluates 2,200 expert-written questions, including multi-paper biomedicine and other scientific domains, using retrieval baselines, citation accuracy, expert rubrics, and human comparisons. Its standard RAG baseline concatenates top-N passages; OpenScholar adds domain-specific retrieval, reranking, iterative self-feedback, and citation verification. On the reported Scholar-CS task, OpenScholar-GPT-4o improves the rubric score over GPT-4o alone and standard RAG; ablations show drops when reranking, feedback, or final attribution is removed. However, even a model with a 128k-token context degraded after too many retrieved passages, and PaperQA2 could have good citation accuracy while covering too few papers ([Nature full paper, methods and results](https://www.nature.com/articles/s41586-025-10072-4.pdf), especially pp. 1–3).

**Source-supported.** The same study found that non-retrieval models often produced plausible but fabricated or unsupported citations, and that citation presence is not equivalent to citation correctness. Its evaluation therefore scores correctness, coverage, citation accuracy, and expert judgments separately. This supports treating a D3 error despite cited counts as a synthesis/interpretation failure rather than assuming retrieval was inadequate.

**Inference for `rob2-kit`.** For D3 traces, compare the cited participant counts with the exact selected passages and the question's required premise: denominator, randomized population, outcome availability, missingness reasons, and true-value dependence. A count citation may be accurate yet insufficient for 3.3/3.4. Add an offline “premise completeness” annotation to evaluation; do not add a runtime critic or extra tool until an ablation shows it repairs D3 errors without inventing unsupported relationships.

## Ranked next ideas tied to current traces

1. **Isolate retrieval versus synthesis for the Krolewiecki r52/r89 pair.** Reconstruct both captured trajectories offline and record when main p4 was surfaced, previewed, opened, and used in Evidence. A new controlled intervention would require fresh paired runs with model, source, Result, and budget held fixed; replay alone cannot establish an accuracy gain. This diagnostic uses existing deep cache/cursors.
2. **Measure evidence-premise completeness for D3.** For each cited-count answer, score whether the cited Evidence establishes the full official 3.1–3.4 premise, not merely a numerator or flow count. Compare errors by answer type (Probably/NI/definitive) and Source role. This directly tests why cited counts still produced D3 reasoning errors.
3. **Run the bounded whole-paper/intro-plus-retrieval experiment.** Use the design above, stratified by paper length and relevant-section position. This tests whether an upfront main-paper orientation reduces misses without dumping all text into every Domain context.
4. **Instrument the 1,854-search trace before changing retrieval.** Break the 645 no-hits down by lexical mode, term count, Source scope, query repeat, and available cursor. Explain the 8 cursor uses: unnecessary, undiscovered, or not useful. Only then test one bounded question-card reformulation policy.
5. **Defer new tool layers.** The papers support better measurement, selective context, and controlled reranking/reformulation experiments; they do not justify another MCP tool, multi-agent voting, or a second scientific assessor. Any such addition should require a preregistered, held-out improvement in exact premise grounding and auditability.
