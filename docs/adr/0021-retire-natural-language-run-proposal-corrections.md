# Retire natural-language Run-proposal corrections in favor of structured operations

`SubmitRunProposalRequest.correction` parses a closed sentence grammar containing the same exact issued Trial, Outcome-target, Result, and Result-candidate identifiers already represented by `RunProposalSelection`, then duplicates validation that the engine performs on the structured selection. It adds no correction capability, looks more permissive than it is, and caused issue #122's generic grammar error when issue #120 left no Outcome-target identifier to reference. We remove the field, regex parser, normalization and merge path without a compatibility alias, and make versioned structured selections and promotions the sole proposal-update contract. `SubmitRunProposalRequest` moves to v2 while new proposal-discovery and Result-mapping operations begin at v1; obsolete clients fail explicitly rather than silently losing candidate, promotion, receipt, or limitation state.

We reject extending the prose grammar to declare new outcomes or improving its error messages: both would preserve a second serialization and validation path for concepts now expressed by typed promotion and selection operations. The project is in active early development, and no demonstrated external caller reliability benefit justifies a deprecation shim.
