# Discovery candidates are advisory; nothing binds identity except an explicit disposition

Pre-confirmation discovery — Source-role inference, Result-candidate matching, and registry (NCT) discovery — previously bound identity directly from a heuristic: `_classify` assigned a Source's role from folder position and filename, Result-candidate matching accepted a case-folded substring hit, registry discovery accepted an identifier-shaped match, and a Trial with exactly one Result candidate was treated as resolved by cardinality alone. None of this was reviewable or reversible without editing code. We introduce one shared `Discovery candidate` shape (cue, location, parser/revision identity, uncertainty) for all three, with a 4-state `Discovery candidate disposition` (accepted, rejected, superseded, unresolved) that only an attributable review can set — including when a candidate is the only one found. `Result candidate` and `Registry candidate` already existed as types but lacked this disposition contract; `Source-role candidate` is new, since `_classify` previously had no candidate wrapper at all. The `Trial discovery record` aggregates them per Trial and gains a new revision on every disposition change, with no separate closed state, matching how `Run proposal` and `Evidence review revision` already work. We rejected keeping the heuristics as silent defaults with an optional override, because that reproduces exactly the "only match wins" failure mode this decision exists to remove — a UI can still make single-candidate acceptance one click without pre-checking it.
