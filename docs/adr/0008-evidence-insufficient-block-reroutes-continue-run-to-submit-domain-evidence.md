# An `evidence_insufficient` block reroutes `continue_run` to a fresh `submit_domain_evidence` work item, not a new correction contract

Issue #127 (folding in #128) found that #114's terminal guard correctly fails closed on unsupported real answers, but its recovery text ("resume by submitting Domain evidence, then resubmit these answers") was a dead end: `continue_run` re-issued the same blocked `submit_domain_answers` work item forever, with no route back to evidence submission. We reject adding a `CorrectDomainEvidenceRequest`/`correct_domain_evidence` contract symmetric to the existing `CorrectDomainAnswersRequest` (the issue's candidate direction 2), and instead fix `continue_run`'s work-item derivation so an `evidence_insufficient` condition routes back to a fresh `submit_domain_evidence` work item for the affected Domain, reusing the existing work-token/idempotency machinery — the handler already knows how to freeze a non-empty bundle for a Domain, so this is a router fix rather than new surface area. "Fresh" means that the corrected submission receives a distinct engine-issued work item, Work token, and idempotency identity: the prior identity remains reserved for exact lost-response replay and can never commit changed content. Retry identity derives deterministically from the latest applicable `domain-evidence-insufficient` Workflow event, so repeated derivation without a new block returns the same token while every subsequent block creates a new attempt. The new token still carries forward any unfrozen `SearchCoverageRecorder` state already accumulated for that Domain's signaling questions (see ADR-0007) rather than discarding it, so evidence a caller already found and dispositioned before hitting the block is not lost — discarding it would reproduce a milder version of the exact failure (real, correctly-sourced evidence that couldn't be recorded) this issue exists to fix. Because the blocking Workflow event is already durable, an affected existing Run derives its fresh retry identity after upgrading without migration, abandonment, or repeating earlier Domain work.

Combined with this, `submit_domain_evidence` now rejects submissions that supply none of: non-empty `passages`/`items`, `no_information_basis=true` with valid receipts, or `coverage_state="incomplete"` with `coverage_limitations` populated — closing the gap where an evidence-free submission was silently accepted (#128) now that a real receipt is actually obtainable (ADR-0007).
